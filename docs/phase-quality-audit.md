# Phase quality audit — 2026-10-05

> Current planning: [full curriculum audit — 2026-10-06](full-course-audit-2026-10-06.md) and [course expansion plan](course-roadmap-2026-10-06.md). This document preserves an earlier delivery snapshot.

> This audit covers the 17-phase, 88-lesson baseline. The subsequent [pretraining and post-training expansion](pretraining-posttraining-expansion.md) adds two phases, nine lessons and two projects, with its own execution scope.

## What was reviewed

All 17 canonical phases, all 88 lesson objectives/section structures/practice prompts/diagnosis fields, project mappings and ten route manifests were inspected. Close reading and numerical changes focused on the deployment and new operations material. This audit is a teaching and integration review, not independent expert verification of every statement or a learner comprehension study. Previous CPU receipts establish reference execution, not educational effectiveness.

## Main findings and improvements

1. **Phase pages lacked a learning journey.** They exposed descriptions and lesson lists but no concrete starting diagnostic, sequence of learner artifacts or transfer question. Each phase now has an original study guide with a worked readiness answer, linked milestones covering every lesson in order, a changed-condition task with reasoning, a failure diagnosis and specific completion evidence. Guides are available from the catalog and every lesson, and are generated into phase READMEs in the downloadable workspace.
2. **Precision teaching stopped short of a complete affine operator.** `deployment-05` now works through activation zero points, accumulator units, bias quantization, output requantization and saturation. An independent real-valued reference checks exact hand-derived accumulators and output codes. A second plot explains offset error versus clipping. Transfer work changes the code origin without changing predictions, checks bias-only outputs and rejects invalid scales. The example explicitly distinguishes NumPy arithmetic from native runtime rounding or kernel behavior.
3. **Evaluation coverage could be misunderstood.** `operations-07` now freezes case IDs, accepts reordered responses and rejects missing, duplicate and unknown response IDs. A failed answer remains in the denominator. The original complete replay was valid; the new lab teaches how incomplete concurrent work can otherwise produce misleading scores. It still does not claim live-model quality.
4. **Four deployment hints repeated generic advice.** These now point to the actual failure mechanism: preprocessing, shape/finiteness, integer scale units or missing device measurements.
5. **New engineering catalog evidence was vague.** Tracking, containerization, MLOps, LLMOps and ModelOps now have demonstrable objectives and specific retained artifacts rather than a generic request to save outputs.
6. **Deployment order obscured the lifecycle.** Adaptation now precedes interoperability and export; containerization precedes service capacity planning, with edge conversion last. Existing lesson IDs and saved progress identities are preserved; explicit prerequisite links follow the new order.
7. **Availability obscured the next depth gaps.** Every guide explicitly states its remaining work. Fully authored does not mean comprehensive; hardware qualification, realistic datasets and independently completed learner work remain distinct concerns.

## Phase-by-phase findings

| Phase | Improved teaching focus | Material still missing or limited |
| --- | --- | --- |
| [00 · Setup & first steps](../phases/00-welcome/README.md) | Can someone else reproduce your first result? Compare interpreter paths before changing packages; launch both from the intended environment. | Fresh-machine Windows/Linux/macOS walkthroughs and novice usability sessions remain unverified; accelerator setup needs a separately observed device run. |
| [01 · Arrays & pure functions](../phases/01-arrays/README.md) | Can you spot a wrong axis even when the program runs? Write the two shapes before broadcasting and test one row and one column independently. | Sparse and ragged inputs need additional contract-focused labs; this phase deliberately teaches fixed dense arrays first. |
| [02 · JAX transformations](../phases/02-transforms/README.md) | What changes when you differentiate, batch or compile a function? Identify the data-dependent truth test. Use a JAX control-flow operation with compatible branch outputs; do not mark changing array data static to suppress the symptom. | Transformation combinations involving nondifferentiable boundaries require further examples; passing smooth fixtures does not validate arbitrary gradients. |
| [03 · State, randomness & control flow](../phases/03-state/README.md) | Have you saved everything needed to determine the next step? Keep carry structure, shapes and dtypes fixed. Return the per-step history through scan outputs. | Local deterministic state does not establish concurrent-writer or multi-host recovery; the recovery and operations phases extend these boundaries. |
| [04 · Math & optimization](../phases/04-optimization/README.md) | Can you explain an optimizer’s behavior from the objective and data? Check the update sign, loss reduction, feature scales and largest quadratic curvature before trying a different seed. | Constrained, nonsmooth and large-scale stochastic optimization are not covered comprehensively. Current ranking evidence is limited to declared synthetic objectives. |
| [05 · Neural network training](../phases/05-networks/README.md) | Did the network learn the task, or exploit an evaluation mistake? Compare state snapshots and train/eval flags; stochastic or running-statistic behavior may still be active. | Natural-image dataset ingestion, richer augmentation studies and pretrained vision transfer remain larger follow-up labs; synthetic images do not establish real-photo generalization. |
| [06 · Data & checkpoint recovery](../phases/06-recovery/README.md) | Can an interrupted run make exactly the same next update? Inspect completion and publication order. An asynchronous save request is not proof that the artifact is durable or restorable. | Network storage failures, concurrent checkpoint writers and true multi-host recovery still need separate failure-injection qualification. |
| [07 · Transformers & language models](../phases/07-transformers/README.md) | Can you prove that a predicted token cannot see its future? Count permitted keys in every query row. A fully masked softmax needs an explicit invalid-query policy; its output and loss must not become valid training evidence. | Real-corpus curation, tokenizer tradeoff studies, long-context evaluation and live generative quality need further labs beyond the tiny byte-model harness. |
| [08 · Performance diagnosis](../phases/08-performance/README.md) | What measured evidence identifies the bottleneck? Check equivalent work, compilation reuse, synchronization, sample spread and competing system activity; retain the raw samples. | CPU traces do not characterize TPU/GPU communication or memory. Target traces and sustained workload measurements remain required for accelerator claims. |
| [09 · Distributed training](../phases/09-distributed/README.md) | Is the distributed update still optimizing the same objective? Check whether local means were summed without count normalization. Verify one complete update before interpreting a training curve. | Real network collectives, multi-controller ingestion and host-loss recovery are unqualified. The optional launch instructions are preparation, not execution receipts. |
| [10 · Scientific computing](../phases/10-science/README.md) | Are you fitting the physical model or the solver’s error? Compare solver error and parameter estimates across resolutions before attributing the shift to physical variation. | Adaptive solvers, event handling, stiff systems, PDEs and domain-specific physical validation remain outside the scalar ODE lab. |
| [11 · Probabilistic modeling](../phases/11-probability/README.md) | Which uncertainty does your model actually represent? Check whether you plotted latent or observation uncertainty, and whether the likelihood or mean function misses structure. | General hierarchical models and robust modern diagnostic workflows need further examples. The instructional sampler is not a replacement for validated inference libraries. |
| [12 · Reinforcement learning](../phases/12-rl/README.md) | Is the policy improving under a fixed evaluation protocol? Check that old log probabilities were stored at collection rather than recomputed from the current policy. | Continuous actions, value-function estimation and larger benchmark environments need new implementation and evaluation labs; this tabular task is deliberately bounded. |
| [13 · Pallas kernels](../phases/13-kernels/README.md) | Does a custom kernel earn its complexity? Inspect operand-specific index maps and boundary masks; square dimensions can hide an axis swap. | Actual TPU/GPU compilation, race diagnosis and target tuning remain unqualified; CPU interpretation cannot close these gaps. |
| [14 · Autodiff & JAX internals](../phases/14-internals/README.md) | Which mathematical operation does the transformed program represent? Inspect captured constants, detached values and custom rules. Compare both primal and derivative behavior at changed base points. | The tiny interpreter is intentionally incomplete. Production extension APIs, effects and full compiler transformation coverage require further targeted work. |
| [15 · Deployment, interoperability & edge AI](../phases/15-deployment/README.md) | Does the exported service preserve the model’s complete contract? Inspect load-time expansion, fallback operators, transfers and preprocessing on the named runtime. File size is not a kernel or latency measurement. | Actual edge-device delegates, thermal/energy budgets, packed low-bit kernels and production serving loads remain unqualified. The revised sequence moves adaptation before export and containerization before service capacity planning. |
| [16 · Workload operations](../phases/16-operations/README.md) | Can you detect, explain and safely recover a failed model release? Require per-slice counts and quality thresholds. Do not average slice means equally or treat a missing critical slice as a passing zero. | Authenticated review, multi-writer promotion, staged cloud rollout, SLO alerting and live-model abuse evaluation still require separate infrastructure and application-specific labs. |

## Next content priorities

These are remaining work, not newly delivered capabilities:

- **A real-data ingestion and evaluation bridge:** dataset permissions/provenance, group/time splits, fitted preprocessing, class imbalance and slice uncertainty, carried through one modality harness. Start with a bounded openly licensed dataset and compare with the current synthetic reference; do not replace reproducible fixtures with an uncontrolled download.
- **A complete text-application lab:** retrieval/index versioning, actual model responses, tool failures, injection resistance, timeout accounting, latency/cost and human-reviewed evaluation cases. Current controlled replay teaches evaluator contracts but is not this application.
- **A production delivery lab:** authenticated artifact access and reviewer identity, image scanning, staged promotion, service-level objectives, alert response and deployment rollback. Local Docker and single-writer pointer checks remain deliberately bounded.
- **Target-device qualification:** real accelerator collectives and failure drills, edge delegates, measured peak memory/thermal behavior and supported packed precision. Keep hardware and billing decisions separate from these CPU exercises.
- **Specialist depth:** stiff/adaptive scientific solvers, hierarchical probabilistic models and robust sampler diagnostics, continuous-control/value-function RL, and target-executed kernel tuning. Each deserves a coherent implemented project rather than another overview paragraph.
- **Learner trials:** fresh-machine setup, timed independent project attempts and misconception interviews. Collect where learners stall and which explanations repair the misunderstanding before assigning validated completion times or claiming career readiness.
