# 07 — Project overview and stage workspace

Route: `project.html?id=<id>`; support existing stage anchors. Applies to regression audit and classifier projects.

## Overview — desktop

```text
Course / Foundations / Regression audit
Prove that your model learns.
Laptop CPU · project workspace available

YOU WILL KEEP                         YOUR PROJECT STAGES
Runnable implementation              1 Shapes and predictions
Gradient check                       2 Gradient checks
Training measurements                3 Training
Reproducibility report               4 Held-out results
                                     (labels from project manifest)
[Download workspace]                 [Open first stage]
> Required lessons                   [View prerequisites]
> Reference implementation
```

The overview explains the deliverable before terminal commands. Open first stage uses last saved stage when available and changes to Resume stage. Download does not report completion. Project titles, commands, stages, expected results, and rubric come from existing manifests.

## Stage — desktop

```text
STAGE NAVIGATION              STAGE WORKSPACE
1 Shapes                      Stage 2: Check gradients
● 2 Gradients                 Outcome / implementation contract
3 Training                    Edit: actual file and function names
4 Results                     Command                  [Copy]
                              Expected output / tolerances
                              > If the check fails
                              [ ] I ran my implementation and kept evidence
                              [Save stage work] (optional)
                              [Previous stage] [Next stage]
```

OS instruction choices are radio tiles, inherited from setup when explicitly saved. Reference commands remain a separate disclosure with their purpose labeled. Stage progression is manual: the static website cannot observe external checker execution. Reported stages are editable, and reopening them keeps exact commands accessible.

## Mobile

```text
[← Project overview]                  [Stages]
Stage 2: Check gradients
Contract → file → command → expected result
> Diagnose a failure
[ ] Practice reported
[Save work]
[Previous]                         [Next stage]
```

Stages opens a vertical list, not a select. One project stage has a stable URL anchor; sharing it does not share private local progress.

## Finish / blocked states

At final stage show a rubric, reported practice summary, Save project work, and Open synthesis assessment if an authored assessment exists. Do not award a pass based on checkboxes.

Missing prerequisites: offer Open required lesson and Continue with project; no fabricated eligibility lock. Planned project: show actual available preparation and omit download/start controls. Invalid project ID: back to available projects. Download failure: retry and source link. Save failure: keep reported status in memory, indicate unsaved, and allow export.

Acceptance: users can reach the current stage without scrolling past every setup command; they can revisit all stages and inspect their own versus reference commands without ambiguity.
