## Before you start

- Required earlier lessons and background.
- Hardware: CPU / GPU / TPU / multiple devices.
- Tested environment and package versions.
- Learning objectives stated as things the learner can demonstrate.

## The problem

A small, concrete task. Explain why the result matters to this phase's project.

## The idea

Use intuition, a diagram, and just enough mathematics to explain the experiment.

## Build it

A minimal implementation or calculation. Show how to run it and the expected output.

## Use it

Apply the same idea with JAX or the appropriate ecosystem library. Explain the mapping.

## Change it

An exercise with a prediction before execution. Label its difficulty.

## Break, diagnose, and fix

One realistic failure. Explain how evidence leads to the diagnosis.

## Verify

Numerical or behavioral checks, with tolerances and hardware constraints. A speed claim needs synchronized timing, warmup, and a stated workload.

## Keep the evidence

Runnable artifact, environment, command, observed output, one changed condition, and the learner's explanation.

## Checkpoint

A question or practical task that tests the objective. Put solutions behind a reveal or in a separate solution file.

## Continue

Previous lesson, next lesson, phase project, and links to primary references.
